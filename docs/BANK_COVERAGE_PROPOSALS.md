# Whole-charge funding

The daily 5:30 p.m. America/New_York profile check imports individual checking debits and creates one unapproved draft per uncovered charge. Each charge uses the first configured, enabled source able to cover its **entire** amount after reserves and existing draft allocations. An insufficient source is skipped; charges are never split and the checking balance deficit is not added to charge amounts. A negative posted balance and an overlapping pending total are not separate charges.

`bank_funding_charges` stores canonical checking identity, provider transaction aliases, amount, date, description and draft linkage. The explicit `pending_transaction_id` joins pending and posted versions; matching amounts alone never establish identity. A completed funding draft leaves a permanent charge link, preventing repeat funding. Cancellation suppresses recreation. Removed charges block approval/preparation. Amount changes revoke an unprepared draft's approval and require a new review. Internal transfers and loan repayments with provider classifications are excluded to avoid circular funding.

`bank_funding_feeds` chooses a single transaction reader for each canonical checking account, avoiding duplicate imports through shared logins. Review refreshes that reader when needed. The first import retains posted history for explicit manual selection, rather than automatically funding historical expenses. Pending entries and new posted debits after initialization are eligible. Missing transaction identities or currency evidence are never synthesized from a pending sum. A manual charge and a later same-date/same-amount bank entry are held as a possible duplicate, not automatically funded twice.

Manual entry selects a banking profile's permitted credit-line-to-checking route and either a known bank charge or a missing charge with a reference, date and full amount. References and potential duplicate amounts/dates are checked under the tenant lock. Both scheduled and manual drafts require explicit review before bank preparation. Source capacity is rechecked on review, approval and preparation. The user alone submits the bank transfer.

An older aggregate coverage draft has no charge attribution, so new automatic charge funding for that checking account waits for it to be resolved. No historical scheduler run is replayed on deployment. The queue polls stored drafts without a Plaid call. Schema changes add two tables through the existing application startup table creation; deploy Web successfully before the worker.

Validation includes the $286.86 and $350 example, skipping a $11.64 HELOC, repeated runs, source reservations, shared logins, pending-to-posted identity, amount changes, removed debits, manual duplicates, cancellation and mandatory review. No real bank transfer is used for QA.
